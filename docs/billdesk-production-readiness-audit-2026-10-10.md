## Audit fixes and tests

Two BillDesk-only compatibility fixes were made: Create Order `order_date` no longer includes milliseconds, matching BillDesk's `YYYY-MM-DDThh:mm:ssTZD` description; and hosted-page extraction now uses the `redirect` relation documented for the full-redirect flow. Synthetic fixtures were updated. No Paytm or PayGlocal implementation was changed.

Fresh results this audit: BillDesk suite **232/232 passed** (10 files); JOSE suite **18/18 passed**; TypeScript `--noEmit` passed; ESLint on the five changed BillDesk source/test files passed; `git diff --check` passed. An initial Vitest run did not execute tests because the Windows sandbox denied writes to its default temporary directory; the rerun with a workspace-local temp directory passed. The JOSE command requires the available Node 24 runtime; the first attempt under Node 22 failed before tests ran, then 18/18 passed under Node 24. No fresh production build was run after these two narrow edits; the prior isolated webpack production build and 257 unique test passes are recorded in the earlier handover report. The earlier disposable PostgreSQL validation reported 15/15 concurrency/recovery scenarios; it was not repeated and is **not** evidence for any cloud database.

Official source comparison: [Authentication and Endpoints](https://docs.billdesk.io/reference/authentications-and-endpoints), [Create Order](https://docs.billdesk.io/reference/createorder), [Retrieve Transaction](https://docs.billdesk.io/reference/post-payments-v1_2-transactions-get), [Neo Full Redirect](https://docs.billdesk.io/docs/neo-full-redirect), and [Webhooks](https://docs.billdesk.io/docs/webhooks-lcm-notifications). Public examples do not establish this merchant's exact profile or whitelist state.

## Prioritized path to production

1. **Company infrastructure:** identify/approve separate UAT Vercel and Supabase project IDs and HTTPS app/adapter domains; establish a synthetic-data UAT database and tester login. Do not use either visible Production-labeled project as UAT by assumption.
2. **BillDesk written profile:** confirm key encoding/length, JWE and JWS algorithms, whether one `kid` serves both, response `kid`/`clientid`, BD-Timestamp format/timezone/skew, item code, device/MAC fields, exact hosted URL/form parameters, callback and webhook schema/URLs, supported payment methods including international cards, and UAT whitelist of `64.225.85.27`.
3. **UAT deployment approval:** configure separate UAT secret stores and HTTPS adapter; verify strict authentication, durable replay/operation state, request/response limits, and outbound IP from the running adapter. Apply migrations 0018–0020 only to the isolated UAT database; rerun concurrency/recovery there.
4. **UAT payment authorization:** run controlled success, failure, cancellation, pending, duplicate/out-of-order callback/webhook, timeout, interrupted checkout and ambiguous-outcome cases. Reconcile by Retrieve Transaction. For success, verify matching BillDesk transaction ID, merchant, order, INR amount and 356 currency in the gateway response and database; confirm one claim, one parent order, expected child orders/fulfillment effects, and no duplicate email/benefit. Verify failed/pending cases never mark an order paid. Check webhook acknowledgement timing and provider retries.
5. **Production approval and rollout:** review abuse controls, recovery runbook, monitoring and rollback; separately configure production merchant profile, whitelist, HTTPS adapter and database migration. Deploy a reviewed revision with BillDesk disabled, validate health/configuration, then enable public selector and upstream only with explicit production approval. Roll back by disabling BillDesk flags while preserving claims, attempts and fulfillment evidence for reconciliation. Recheck Paytm/PayGlocal after deployment.

**No end-to-end BillDesk payment or verified production payment record exists in this audit.** A local build or simulated test cannot substitute for an authorized UAT transaction and its database evidence.
